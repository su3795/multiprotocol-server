# 多协议集群服务器 · 快速启动

## 零门槛验证（无需任何工具链，只要有 Node）

保存 mp-all-in-one.js，然后：

    node mp-all-in-one.js test      # 单元测试 23 项
    node mp-all-in-one.js e2e       # 端到端 15 项（真实 socket）
    node mp-all-in-one.js golden    # 打印 golden 向量
    node mp-all-in-one.js server    # 启动服务端（TCP 9101 / UDP 9201 / CUSTOM 9301 / KCP 9401）
    node mp-all-in-one.js client --proto tcp --port 9101

这是整个交付中唯一真实运行并跑通的代码。

## 四套实现

| 项目 | 语言 | 说明 |
|---|---|---|
| multiprotocol-cluster.zip | Java | SOFAJRaft + Aeron Cluster 双模型 |
| multiprotocol-cluster-go.zip | Go | 默认零依赖 |
| multiprotocol-cluster-rust.zip | Rust | 默认零依赖 |
| reference-impl.zip | Node | 参考实现（可运行） |

均支持五种协议：TCP / UDP / CUSTOM / KCP / QUIC（QUIC 默认关闭）

## 快速开始

### Go 版（推荐先跑这个）

    cd multiprotocol-cluster-go
    go vet ./...
    make test
    make build
    ./scripts/start.sh
    ./bin/mp-client --proto tcp --port 9101
    ./scripts/stop.sh

一条命令跑完整端到端：

    make e2e

### Rust 版

    cd multiprotocol-cluster-rust
    cargo check
    cargo test -p mp-common -p mp-gateway
    cargo build --release
    ./scripts/start.sh
    ./target/release/mp-server client --proto tcp --port 9101
    ./scripts/stop.sh

### Java 版（SOFAJRaft）

    cd multiprotocol-cluster
    mvn clean package -DskipTests
    ./scripts/start-jraft.sh
    ./scripts/test-tcp.sh
    ./scripts/stop.sh

### Java 版（Aeron Cluster）

    cd multiprotocol-cluster
    mvn clean package -DskipTests

    # 必须：放大共享内存，这是 Aeron 启动失败的头号原因
    sudo mount -o remount,size=1G /dev/shm
    df -h /dev/shm

    ./scripts/start-aeron.sh
    ./scripts/test-tcp.sh
    ./scripts/stop.sh

## 故障排查

Java:
    EventCode 找不到        -> Aeron 部分版本改名为 ClusterEvent，换 import
    Aeron 启动失败          -> /dev/shm 不足，执行 mount -o remount,size=1G /dev/shm
    UnsupportedClassVersion -> JDK 低于 11

Go:
    module not found        -> 默认构建不应发生；用 -tags 时需先 go get
    KCP 一直超时            -> 看 logs/server.log 确认 KCP 端口起来了
    dragonboat 签名错误     -> 对照官方 example 核对 SyncPropose / SyncRead

Rust:
    let else 语法错误       -> Rust < 1.65，升级到 1.70+
    spawn_blocking 不工作   -> Tokio 未启用 rt-multi-thread
    quinn 编译错误          -> 0.10 与 0.11 的 Endpoint::server 签名不同

通用:
    端口被占用   -> lsof -i :9101
    选不出 Leader-> 检查 peers 配置、防火墙、时钟偏移
    写请求失败   -> 只有 Leader 可写

## 常见问题

四套能互通吗？
    能。共用同一帧格式（magic 0x4D50 大端、20B 头、CRC32），
    任意服务端 + 任意客户端可组合。

为什么默认用内存 Raft？
    保证零依赖开箱可跑。生产请切 dragonboat（Go）/ openraft（Rust）。

QUIC 为什么默认关？
    需外部库 + TLS 证书，与「零依赖开箱可跑」冲突。
    三版均用构建开关隔离，未启用时不影响默认构建。

单条消息大小限制？
    KCP 分片数 <= 255，约 255 x 1376 = 345KB。TCP/UDP 无此限制。
